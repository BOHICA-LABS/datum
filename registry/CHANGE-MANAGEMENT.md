# Landing the registry

This is a change to a **running factory across ~24 projects** (12 with a `.factory`, 10
with a populated contract set, 12 more scaffolded). Per issue #671's own warning about its
later phases, it goes through vsdd's change management — an ADR, stories, and a policy with
`enforced_by` — not a unilateral rewrite.

**The constraint that shapes everything below:** the registry currently reports **18,418
conformance findings** against the three corpora. Every one is either a real drift or a
tightening this registry introduces. A gate turned on at `block` on day one would fail
every PR in every project and be switched off within a day. That is
[DECISIONS](../research/DECISIONS.md) D3's whole point, and it is why every type ships at
`advisory` and graduates per type.

---

## 1. The ADR to open

**Title:** `ADR-NNN — artifact type registry: declare artifact SHAPE, not only artifact PATH`

**Context.** `artifact-path-registry.yaml` (ADR-016) calls itself the single source of
truth for canonical `.factory/` locations and declares only `canonical_path_pattern` +
`enforcement_level`. Nothing declares what an artifact *is*, so:

- `document_type` drifted to **181 non-canonical values over 1,138 files** across three
  corpora, none of them present in the 81 the templates declare.
- Two projects on the same factory share **ZERO** `verdict` values.
- **17 types** are declared in one of the two registries and not the other; the two
  namespaces overlap on only **11 of 46 / 81** names.
- 4 different BC totals coexist because indexes are authored rather than derived.

**Decision.** Adopt `artifact-type-registry.yaml` as the declaration of artifact shape,
alongside (not replacing) the path registry, with the four one-way doors settled as D-A
through D-D in the registry header.

**The one decision this ADR must make that is bigger than the registry:** the two
namespaces must be **reconciled into one**. Options, with the recommendation:

| option | consequence | assessment |
|---|---|---|
| **Merge path registry INTO the type registry** (recommended) | one file declares path + shape per type; `artifact_type` and `document_type` become one vocabulary | The only option that removes the defect rather than documenting it. 17 renames, all mechanical. |
| Keep both, add a mapping table | the mapping is a third thing to drift | Cheapest today, and it recreates the problem one level up. |
| Keep both, declare them independent namespaces | requires every consumer to know which is which | Rejected: 8 path-registry names are already in live use as `document_type` values, so they are not independent in practice. |

**Alternatives considered.** Issue [#671](https://github.com/drbothen/vsdd-factory/issues/671)
(`factory-graph`) — an in-tree Rust crate rehydrating a `petgraph` from markdown with no
database. It is an **open, unbuilt proposal by another author on the same repo** and under
the new vision the two are a **fork in the road, not complements**: #671 keeps markdown
authoritative forever, this keeps `fa` authoritative. #671 should be answered on the issue
rather than left open and silently contradicted. Two things from it survive regardless and
are stories below: **body-prose reference extraction** and its phase-1 exit criterion
(**reproduce the known F-\* findings**), which `fa` has never been checked against.

**Consequences.**
- 275 plugin files reference `document_type` as a KEY — the key is stable, only VALUES
  change: a mechanical frontmatter rewrite with a reviewable diff.
- `cycles/` paths appear in **189 plugin files** and `tech-debt-register` in 12. Those are
  the couplings to sequence carefully because paths are embedded in prompts.
- `verdict`, `delta`, `changelog` and `input-hash` are retired as stored fields. `input-hash`
  alone appears in **3,890 files**.
- Directory renames are `git mv` plus a registry entry.

## 2. The policy to register

```yaml
- id: POLICY-NN
  name: artifact-type-conformance
  statement: >
    Every artifact written to .factory/ MUST declare a document_type that is a canonical
    value in artifact-type-registry.yaml (resolving through aliases.yaml), and MUST satisfy
    that type's declared required fields, closed enums and section schema at the type's
    current enforcement_level.
  rationale: >
    Measured: 181 non-canonical document_type values over 1,138 files, and zero shared
    verdict values between two projects on the same factory. The drift is generated by the
    METHOD — agents name things per session against no declared vocabulary — so no amount
    of per-project tidying fixes it. Only a declared, enforced vocabulary does.
  enforced_by:
    - fa validate --registry            # the gate, findings baselined and ratcheted
    - validate-artifact-type (PreToolUse hook)   # blocks at enforcement_level: block
    - registry/validate_registry.py     # CI: the registry's own completeness gate
  enforcement_level: advisory           # per TYPE; see the graduation ladder below
  exemptions:
    - "types with pending_template: true gate at `info` until a template exists —
       penalising a project for a concept the standard forgot is the registry's defect"
    - "authority: ingested types (semport, logs, research) are never gated on spec schema"
    - "legacy-design-doc is frozen: never validated against a schema it predates"
  anti_pattern_this_replaces: >
    POLICY 5 has been extended SIX times (META-LEVEL 31 -> 36) trying to fix citation
    drift with prose rules, and validate-index-cite-refresh exists solely to police the
    4-index version-cite ledger by hand-rolled string scanning. A policy with no
    mechanical enforcer is a comment.
```

**Rule that keeps the registry honest:** a policy without an `enforced_by` that actually
runs may not be registered. That rule applies to this policy too — which is why
`validate_registry.py` exists and exits non-zero.

## 3. Stories

Ordered by dependency. Each has a mechanical exit criterion, because "the registry is
adopted" is not testable.

| # | Story | Exit criterion |
|---|---|---|
| **1** | **Reconcile the two namespaces.** Merge `artifact-path-registry.yaml` into `artifact-type-registry.yaml`; one vocabulary for `artifact_type` and `document_type`. | `validate_registry.py` reports **0** `registry_namespace_defect` flags (17 today). |
| **2** | **Add the 16 missing templates** for the gap types, largest mass first: `fix-burst-closure` (79 files), `research-note` (66), `remediation-manifest` (31), `wave-gate-report` (30), `proposed-adr` (28), `architect-decision` (19), `uncertainty-map` (13). | Every `pending_template: true` is cleared; 344 files stop being un-typeable. |
| **3** | **Fix the standard's own three collisions.** `traceability-matrix`/`-matrices`, `holdout-evaluation`/`-report`, `consistency-report`/`consistency-validation-report`, plus `ux_spec` — the single underscore in an 81-value kebab vocabulary. | 81 declared values contain no near-duplicate pair; `unresolved:` in aliases.yaml is empty. |
| **4** | **Mint `adversarial-finding` as rows.** A template exists and **nothing uses it** — findings are prose tables inside review bodies. | `finding_count`, `severity_distribution` and `total_findings` become DERIVED on ≥1 real cycle and agree with the prose they replace. |
| **5** | **Split the overloaded fields.** `verdict` → `gate_result`/`convergence`/`severity_max`; `status` → lifecycle only. Migration is table-driven from `enums.yaml: migrated_from`. | 745 `retired-field:verdict` and 356 `enum-*:status` findings reach zero; no value lands outside a closed enum. |
| **6** | **Convert the ledgers to append-only rows.** `burst-log`, `cycle-decision-log`, `lessons-learned`, `session-checkpoints`, `tech-debt-register`. | The nine ledgers with 600+ append commits are rows; two agents appending concurrently produce no conflict (test it, don't assert it). |
| **7** | **Make the indexes derived.** `BC-INDEX`, `STORY-INDEX`, `ARCH-INDEX`, `VP-INDEX`, `cycles/INDEX`, `epic.story_count`. | The 4-way BC count disagreement and the SS-03/05/08 drifts are structurally impossible; `fa`'s 7 `count` findings go to zero. |
| **8** | **Retire `delta-archive`.** Load 211 rivetry sidecars as historical versions of their `source_file`, verify the reconstructed sequence, then delete. | Version count per source artifact equals archived-entry count + live entries; **gated by a count assertion, because this is the only place some versions exist**. |
| **9** | **Retire `input-hash`.** 3,890 files. Replace with derived staleness from `inputs` + history. | `fa` reports staleness for every artifact with `inputs`; no `PENDING-RECOMPUTE` sentinel remains. |
| **10** | **Materialise filename-only keys.** `bc_id` (2,362 files) and `vp_id` (215) exist only in filenames. | Every record carries its key as data; `path` becomes a derived UNIQUE column. |
| **11** | **Split `STATE.md`.** One file, **868 commits**, is three artifacts: a mutable record, a decisions ledger, and a checkpoint ledger. | Three artifacts; then `fa lease` can retire the YAML lock and its CWE-367 TOCTOU race. |
| **12** | **Body-prose reference extraction** (from #671). Needs code-span exclusion, as-of resolution and per-id adjudication or it manufactures false findings. | Reproduces the known **F-\* findings** from recent adversarial passes without hand-tuning — #671's own phase-1 exit criterion, which `fa` has never been checked against. |
| **13** | **Per-project profiles.** Each project declares which canonical types it uses. | 10 profiles committed; `fa validate` uses the profile to decide whether ABSENCE of a type is a finding. |

**#671's exit criterion has now been RUN** — see [FSTAR-COMPARISON](../research/FSTAR-COMPARISON.md).
It reorders this list:

| class of the adversary's findings | share (95% CI) | which story |
|---|---|---|
| derived-data staleness the registry makes **impossible** | **25.3% ±9.1** | **story 7 — the single highest-value change** |
| needs body-prose extraction | 21.8% ±8.7 | story 12, now with known scope |
| frontmatter-reachable | 14.9% ±7.5 | stories 5 + 10 |
| out of reach of ANY parser (external 13.8% · process 12.6% · semantic 11.5%) | **37.9% ±10.2** | none — and the ADR must say so |

So: **story 7 before story 12**, and the ADR must state the 37.9% explicitly. Nobody should
read this registry as replacing adversarial review — over a third of what the adversary finds
is beyond any parser, prose-capable or not. Method caveat: A (25.3%) and C (21.8%) overlap
within their intervals, so "derived beats prose" is the direction and not a proven ordering;
it would take n≈400 to separate them, and both are worth doing regardless.

## 4. The graduation ladder

Per type, never globally. Composes with `fa`'s existing dated baseline.

```
advisory ──► warn ──► block
   │           │        │
   │           │        └─ that type's baseline is ZERO (or every item waived
   │           │           with a reason) AND the gate has caught ≥1 real
   │           │           regression in a real PR      [DECISIONS D3]
   │           └─ the type has a template, an alias entry for every observed
   │              spelling, and its finding count is falling
   └─ every type starts here. Findings are recorded, nothing is blocked.
```

**Suggested first cohort to reach `block`** — high value, low population, already
schema-conformant:

| type | why it is first |
|---|---|
| `holdout-scenario` | best conformance measured: all 15 required fields present in every one of 21 files AND template-declared |
| `ux-spec-flow` / `ux-spec-screen` | all required fields present on all 38 rivetry files |
| `adr` | `adr_id`/`date`/`subsystems_affected` present on all 130 files across all three corpora |
| the derived indexes | once derived, conformance is unconditional — there is nothing to author wrongly |

**Deliberately NOT in the first cohort:** `adversarial-review`. It is the largest type
(725 canonical + 425 aliased) and only `document_type` itself is present in ≥95% of files
today, so all 8 of its required fields are a tightening. It targets `warn`, and reaching
`block` there is a project, not a step.

## 5. Sequencing hazards, named so they are not discovered late

1. **`cycles/` paths are embedded in 189 plugin files.** Any directory rename in the cycles
   tree is a prompt change, not a data change. Sequence it after the vocabulary work, never
   with it.
2. **Story 8 is data-bearing.** `delta-archive` holds versions that exist nowhere else.
   Count-assert before deleting; a fill-then-delete with no assertion is how a migration
   silently loses history.
3. **`prd-supplement` needs per-file adjudication.** prism uses one generic value with a
   `section` field where the standard declares four types. A bulk rewrite mislabels
   content; the alias is flagged `requires_per_file_adjudication`.
4. **The alias map is a migration device, not a tolerance.** Each entry has a
   `retire_after`. But **history must keep resolving through it forever** —
   `BC-1.12.008` was legitimately renumbered to `BC-3.05.004`, so a flat existence check
   against today's corpus manufactures false findings against correct documents.
5. **108 singleton values are deliberately NOT aliased.** They are 9.5% of the drift mass
   and 60% of the vocabulary. The closed-enum gate is the right instrument; aliasing them
   would make the drift permanent while appearing to fix it.
6. **vsdd-factory must not be the reference implementation.** It is a 7.2×-BC outlier with
   4 singleton directories whose own `holdout-evaluations/` is uniquely named and empty. On
   the two directory-naming disputes measured, **vsdd is the deviant one** and migrates too.
7. **151 prism files sit in 4 `specs/` subdirectories the path registry does not declare at
   all**, while that file's own header states it blocks writes to any unregistered path. So
   either the hook is not running there or the registry was never authoritative — settle
   which before relying on the hook as an enforcement surface.

## 6. What this registry does NOT settle

Recorded so the next session does not mistake silence for a decision.

- **Whether `proposed-adr` should exist** (28 prism files) or collapse into `adr` with
  `status: draft`. `do_not_execute` is load-bearing; both readings are defensible.
- **Whether `runtime-log` entries become rows.** 34 `.jsonl` files, the only genuinely
  high-volume append shape. Left as `blob-with-path` and flagged as *unmeasured*, not as
  decided.
- **`complexity` on `ux-spec-screen`** — its value set was never measured, so the enum is
  deliberately unbound rather than guessed.
- **Growth.** `cycles/` alone is 15.8 MB, mean 26 KB/doc, largest 615 KB, and growth is
  unmodelled (open gap 5). **beads' mitigation is unavailable to us**: it decays closed
  issues ~70% by summarisation and *discards the original*, which an authoritative spec
  corpus forbids.
- **Multi-repo mode** (`.factory-project/`) remains out of scope.

## 7. Reproducing every number in this package

```sh
cd ~/Dev/scrap/dolt-artifact-spike
python3 registry/measure_types.py       # canonical vs actual, per corpus
python3 registry/observe.py             # per-type field/section/enum observation
python3 registry/validate_registry.py   # registry completeness + corpus conformance
```

`validate_registry.py` exits **0** today: the registry is complete over all 225 observed
values and internally consistent. It exits **1** if a new value appears with no
disposition, which makes the registry's own completeness a CI gate rather than a claim.

All three scripts are read-only. `~/Dev/vsdd-factory` and every sibling corpus were
read-only for the whole of this work.
